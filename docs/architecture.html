Architecture & documentation

A search engine that crawls, understands, and answers.

A from-scratch full-stack engine: it crawls the web, indexes pages in Postgres, ranks them with hybrid keyword + semantic search, and writes a cited AI answer on top — with a Redis-backed job queue, caching, and rate limiting that all degrade gracefully when absent.

Node · Express · TypeScript Postgres + pgvector Redis · BullMQ Next.js 16 · React 19 RRF hybrid ranking OpenAI RAG answers

01 — System

How the pieces fit together

One direction of dependency inside the API — routes → controllers → services → repositories → db. All SQL lives in the repository layer; services never touch the driver. The crawl worker reuses the same services as the API: the queue changes when work runs, not how.

02 — Query

A search request, end to end

Search resolves the mode (auto becomes hybrid when embeddings are enabled), checks the Redis cache, embeds the query once, and fuses keyword + vector ranking in a single SQL round-trip. The AI answer retrieves the top sources and writes a cited response — degrading to an extractive summary with no LLM key.

retrieve

Cache-aside

Keyed by an index version so a crawl transparently invalidates stale results. Warm answers return ~10× faster.

rank

Hybrid in one SQL

Full-text and vector KNN ranked in CTEs, fused by RRF, joined back for snippets and an accurate total.

answer

RAG with citations

Top-K sources → LLM answer with [n] markers, or an extractive fallback that always works.

03 — Indexing

Crawl → parse → store → embed

POST /crawl enqueues a job and returns 202 + jobId immediately; a worker crawls (respecting robots.txt, with dedup, politeness delays, and retries), parses, upserts each page + its link graph in a transaction, embeds for semantic search, and bumps the index version. Poll GET /crawl/:jobId for live progress. With no Redis, the crawl runs synchronously instead.

04 — Ranking

Hybrid ranking with Reciprocal Rank Fusion

Keyword and semantic search each return a ranked list. RRF combines them using only positions — no score calibration between two very different scoring systems. A page ranked high by both retrievers wins.

score(doc) = Σlists 1 / (k + rank) // k = 60
// runs in ONE SQL query: 2 CTEs (ts_rank_cd, embedding <=>) → group + sum → join back

05 — Resilience

Every optional dependency degrades gracefully

The system is designed to run in a laptop demo with zero keys and to scale out in production — the same code, driven by configuration.

DependencyWhen presentWhen absent (fallback)
Redisasync queue · caching · distributed rate limitsync crawl · no cache · in-memory limit
OpenAI keyLLM answers · OpenAI embeddingsextractive answers · local/hash embeddings
Embeddingssemantic + hybrid searchkeyword + fuzzy only
Databasecrawl + searchserver boots; /health reports not-configured
retry

Backoff on OpenAI

429/5xx/network retried with exponential backoff before falling back.

queue

Job retries

BullMQ retries failed crawls; crawler retries transient HTTP.

isolation

Best-effort embedding

Embedding failures never fail a crawl — backfill later with npm run embed.
